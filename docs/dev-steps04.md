# プロダクト拡張フェーズ 開発手順 (dev-steps04)

## やりたいこと・基本方針

この段階では firebase-sticky-board をプロダクトとして機能拡張、UI/UXの洗練を段階的に行う。

MVP のフェーズを超えて、プロダクトとして使える、保守拡張しやすいようにしていく。
この段階では最低限の実装でなくてもよい。
実装方針
- MVPではなく、最低限の実装でなくてもよい
- シンプルさの原則
- 読みやすく、認知負荷の小さいコード
- 将来にわたって保守、拡張しやすい設計
- 実務プロダクトとしても通用するコード品質
- 見た目の印象（地味でない、古くない、魅力的）も気にする

作業ペース
- 1日30分から1時間の作業で、1週間から2週間程度でこのフェーズが完成できると嬉しい

実現したいユーザーストーリー
- 私（開発者）がこのホワイトボードソフトウェアを、自分用の日常的に使えるホワイトボードとして、アイデアや考えを試行錯誤しながら表現でき、視覚的・感覚的にも楽しみながら使える。

ユーザーストーリーの達成のため、以下の機能を実現したい。

ボード一覧とボード管理
- ログインユーザーは自分がオーナーのボードを作成できる（既存実装で達成済み）
- ログインユーザーは自分がオーナーのボードを一覧できる
- ログインユーザーは自分がオーナーのボードを削除できる
- ログインユーザーは自分がオーナーのボード一覧から選択してボードを表示、編集できる

付箋操作改善
- ユーザーは空の付箋を追加できる
- ユーザーは付箋にテキストを入力、編集できる
- 初期テキストを入力しての付箋追加操作はこれらが実装された後では不要

UI/UXのアップデート
- （本フェーズではすべてを実装することを目的とせず、優先度の高い項目から段階的に行う）
- （見た目の印象はMiroのようなものをイメージしている）
- 付箋の色がぼんやりしている印象なので、元気のある色テーマにする
- 付箋の形は正方形とする
- 付箋の文字サイズは入力した文字数に応じて、付箋サイズに収まり、かつ最大限文字が大きくなるよう適当に調整される
- 付箋のフォントがかっこわるくないか見直す
- ボード操作UIのレイアウト方法やデザインは適切、整頓されているか見直す
- ボード背景にホワイトボード感が出るようにグリッド線を表示するなど検討する
- ボタンの角丸が少し角ばって見えてかっこわるい。ボタンサイズが小さいせい？
- 現状は全体的に落ち着いたデザインだが、少しかっこわるく感じている。テーマやサイズを見直す

リファクタリング
- 必要に応じて整頓する
- 保守性、拡張性はよいか
- 読みやすく、認知負荷を小さく抑えられているか

## やらないこと

以下はやらない。

匿名ユーザーのボード作成
- 匿名ユーザーはボードをひとつだけ作成できる
- 匿名ユーザーが作成したボードは1時間で削除される

## 開発手順（Phase04）

このセクションでは、本フェーズの具体的な実装手順を定義する。

本フェーズでは、Phase03までのMVPをベースとして、

- 日常的に使える操作性
- シンプルな共同編集体験
- 安定した付箋操作

を実現する。

### 本フェーズの前提方針

共有モデル：

- 共有リンクを知っているユーザーは編集できる
- 匿名ユーザーは閲覧・編集のみ可能
- 匿名ユーザーのボード作成は行わない

付箋操作：

- 空の付箋を追加する
- クリックで編集する
- 編集終了時に保存する

### ゴール（完了条件）

- [ ] 空の付箋を追加できる
- [ ] 付箋をクリックして編集できる
- [ ] 編集終了で保存される
- [ ] ドラッグ・色変更・削除が編集と干渉しない
- [ ] Firestore rules が共同編集前提で最低限安全になっている
- [ ] 自分のボード一覧からボードを開ける

### 推奨する進め方（順番）

1. Firestore rules 調整
2. 空付箋追加
3. 付箋編集機能
4. 操作安定化（ドラッグ・編集の整理）
5. 付箋追加UI整理
6. ボード一覧
7. UI小改善
8. 必要最小限のリファクタリング

### 0. Firestore Rules 調整（共同編集前提）

目的：
- 共同編集を許可する
- 想定外データを防ぐ
- データ整合性を保つ

方針：
- notesは認証済ユーザーなら編集可能（匿名含む）
- boards作成は非匿名ユーザーのみ
- notesのフィールドは制限する

作業：
- notes create/update のフィールド制限を追加
- text/x/y/color の型検証を追加
- textの最大長を制限する
- boards create で ownerUid の一致を確認する

完了条件：
- 既存機能が壊れていない
- Board画面が正常動作する
- 不正なデータ更新が拒否される
- 既存の共有リンクが正常に動作する

### 1. 空付箋追加

目的：
- 思いついた内容をすぐ置けるようにする

作業：
- handleAddNote を修正する
- text必須を廃止する
- 初期値を空文字にする

例：
```
text: ""
```

完了条件：
- 空の付箋が追加できる
- Firestoreに保存される

### 2. 付箋編集機能

目的：
- 日常的な編集体験を作る

仕様：
- クリックで編集開始
- textareaを表示
- 編集終了で保存

保存：
- blurで保存する

キャンセル：
- Escキーでキャンセルする

作業：

state追加：
```
editingNoteId
draftText
```

処理追加：
- 編集開始処理
- 保存処理
- キャンセル処理

表示分岐：

通常：
```
note.text
```

編集：
```
<textarea />
```

完了条件：
- クリックで編集できる
- blurで保存される
- Escでキャンセルできる

### 3. 操作安定化（ドラッグと編集の整理）

目的：
- 操作の衝突を防ぐ

方針：
- 編集中はドラッグ禁止

作業：
- editingNoteIdが一致する場合はドラッグ開始しない

```
if (editingNoteId === note.id) return;
```

pointer capture 修正：
```
e.currentTarget.setPointerCapture(e.pointerId)
```

色変更ボタン：
```
onPointerDown={e => e.stopPropagation()}
```

削除ボタン：
```
onPointerDown={e => e.stopPropagation()}
```

完了条件：
- 編集しようとして付箋が動かない
- 色変更時にドラッグしない
- 削除時にドラッグしない
- ドラッグが安定している

### 4. 付箋追加UI整理

目的：
- UIを単純にする

作業：
- showInput state を削除
- text state を削除
- 入力Cardを削除する

変更：

付箋追加ボタン：
- 押すと空付箋作成
- 作成後編集モードに入る

完了条件：
- UIが単純になっている
- 入力Cardが不要になっている

### 5. ボード一覧

目的：
- 日常利用を可能にする

作業：

Top画面：
- onAuthStateChangedでユーザー管理

ボード取得：
```
where("ownerUid","==",uid)
orderBy("createdAt","desc")
```

表示：
- ボード一覧表示
- ボードクリックで遷移

削除：
- ownerのみ削除ボタン表示
- 削除確認を表示

完了条件：
- 自分のボードが一覧できる
- ボードを開ける
- ボード削除できる

### 6. UI小改善（必要最小限）

目的：
- 第一印象を改善する

方針：
- 実装は2項目までにする

候補：
- グリッド背景
- 色テーマ改善
- ボタンサイズ調整
- border-radius調整

完了条件：
- 見た目が改善している
- UIが破綻していない
- 作業量が肥大化していない

### 7. リファクタリング（必要最小限）

目的：
- コードを読みやすくする

方針：
- 過剰な抽象化をしない
- 触った部分を整頓する

候補：
- StickyNoteコンポーネント分割
- Board.tsx整理

完了条件：
- コードが読みやすい
- 状態管理が理解できる

## 補足
